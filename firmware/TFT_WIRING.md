# ESP32 ILI9341 TFT 接线说明

## 硬件前提

- **ESP32 rev 1.1，4 MB Flash，无 PSRAM**（本项目实测的板子）
- **2.8 寸 ILI9341 SPI 屏**，240×320，4 线 SPI（不是 8 位并口版本）

> ⚠️ 屏幕背面若写着 `ILI9341 SPI` / 有 `SCLK / MOSI / CS / DC / RST / BL` 丝印，才是本项目支持的型号。
> 标着 `ILI9341 8-bit parallel` 的排针版本**不适用**。

## 接线表

| TFT 模块引脚 | ESP32 引脚 | 说明 |
|---|---|---|
| `VCC` | `3V3` | 多数 ILI9341 模块支持 3.3V。**不要接 5V**（除非模块明确标注带电平转换） |
| `GND` | `GND` | |
| `SCL` / `CLK` / `SCK` | **GPIO 18** | SPI2 SCLK |
| `SDA` / `DIN` / `MOSI` | **GPIO 23** | SPI2 MOSI |
| `CS` | **GPIO 5** | 片选 |
| `DC` / `RS` | **GPIO 21** | 数据/命令选择 |
| `RST` / `RES` | **GPIO 22** | 复位 |
| `BL` / `LED` | **GPIO 4** | 背光（高电平点亮） |
| `MISO` / `SDO` | **不接** | 本项目只写不读屏幕；不接 MISO 可以省一根线 |
| `SD_CS` / `TF_CS` | **不接** | 模块上 TF 卡座专用，与屏幕无关 |

### 接线图

```
   ILI9341 模块                  ESP32
  ┌────────────┐
  │ VCC        │──────────────► 3V3
  │ GND        │──────────────► GND
  │ SCL / CLK  │──────────────► GPIO18   (SCLK)
  │ SDA / MOSI │──────────────► GPIO23   (MOSI)
  │ CS         │──────────────► GPIO5    (CS)
  │ DC  / RS   │──────────────► GPIO21   (DC)
  │ RST / RES  │──────────────► GPIO22   (RST)
  │ BL  / LED  │──────────────► GPIO4    (背光)
  │ MISO       │   ✗ 不接
  └────────────┘
```

## 与板上已有资源的关系

| 资源 | GPIO | 冲突情况 |
|---|---|---|
| 板载 LED | GPIO 2 | 不冲突，TFT 未使用 |
| BOOT 键 | GPIO 0 | 不冲突，TFT 未使用 |
| 串口 TX/RX | GPIO 1 / 3 | 不冲突（TFT 走 SPI） |

## 配置方式

所有参数在 `firmware/main/Kconfig` 里，改完重新编译即可：

| Kconfig 项 | 默认值 | 说明 |
|---|---|---|
| `TFT_WIDTH` / `TFT_HEIGHT` | 240 / 320 | 屏幕分辨率 |
| `TFT_SPI_HOST` | 1 | 1=SPI2(HSPI)，2=SPI3(VSPI) |
| `TFT_PIN_SCLK` | 18 | |
| `TFT_PIN_MOSI` | 23 | |
| `TFT_PIN_CS` | 5 | |
| `TFT_PIN_DC` | 21 | |
| `TFT_PIN_RST` | 22 | |
| `TFT_PIN_BACKLIGHT` | 4 | 填 -1 表示不控制背光 |
| `TFT_PCLK_HZ` | 40000000 | SPI 时钟，线过长可降到 20000000 |
| `TFT_BGR` | n | 颜色红蓝互换时打开 |
| `TFT_INVERT_COLOR` | n | 颜色整体反相时打开 |

### 屏幕方向（重要）

ILI9341 的 **MADCTL (0x36) 寄存器的 MX 位在竖屏模式下是必选的**。
数据手册参考初始化写的是 `0x48`（MX | BGR），清掉 MX 位会导致**整幅画面左右镜像**。

开机画面有彩条（红→绿→蓝→黄→青→品红→白→黑，**从左到右**）和一个
**左三角 / 右方块** 的不对称标记，可以据此判断方向：

| 现象 | 含义 |
| --- | --- |
| 彩条红色在**左**，文字正常 | ✅ 正确 |
| 彩条红色在**右**，文字反了 | ❌ 整屏镜像，需要翻转 |
| 三角和方块左右互换 | ❌ 整屏镜像，需要翻转 |

固件默认已带 MX 位（`MADCTL = 0x48`）。如果你的屏模块方向不同，
**长按 BOOT 键（1.2 秒）**即可循环切换方向，无需重新烧录：

| 长按 BOOT 次数 | MADCTL 镜像位 | 效果 |
| --- | --- | --- |
| 0（默认） | MX | 竖屏，文字正常 |
| 1 | 无 | 水平镜像（若默认是反的就用这个） |
| 2 | MY | 垂直翻转 |
| 3 | MX + MY | 旋转 180° |

串口日志会打印当前方向：

```
I (812) tft_dash: orientation 0: MADCTL mx=1 my=0 (MX)
```

切到哪个方向文字正常，就说明你的模块需要哪个，把该值固化到
`main/tft_dashboard.c` 的 `g_orientations` 表首项即可。

> **注意**：BOOT 键现在是双功能的 —— **短按**切换页面（仪表盘 ↔ Wi-Fi 网络列表），
> **长按 1.2 秒**切换屏幕方向。

## 屏幕上的 Wi-Fi 网络列表

TFT 模式有两个页面，**短按 BOOT 键**切换：

| 页面 | 内容 |
| --- | --- |
| 仪表盘 | 运行时间、堆内存趋势图、AP 数、RSSI |
| Wi-Fi 列表 | 周边可连接网络：SSID / 加密类型 / 信号格 / 信道 |

Wi-Fi 页面顶部显示当前连接状态与 IP，已连接的网络行前带 `*` 标记。
固件在开机时自动扫描一次，之后每 30 秒重扫。

也可以从 PC 端用串口命令操作（`@CMD SCAN` / `@CMD LIST` / `@CMD CONNECT` /
`@CMD DISCONNECT`），详见项目根目录 [README.md](../README.md)。

## 常见问题排查

### 屏幕全黑 / 全白

1. **先看背光**：GPIO4 是否接对？屏幕亮了吗？亮着但全黑说明是数据问题，不亮说明是供电或 BL 线问题。
2. **看串口日志**，确认有这两行：
   ```
   I (811) tft_disp: disp created: 240x320, 153600 bytes in 10 chunks, dma chunk=3840 bytes
   I (811) tft_dash: tft ready: 240x320, pclk=40000000 Hz
   ```
   没有 = 初始化就失败了。
3. **接 MISO**：`display id: 00 00 00 00` 表示读不到控制器 ID，说明没接 MISO 或读失败。接上 MISO 后应显示 `00 FF 93 xx`（`0x93` = ILI9341）。这一步能直接证明 SPI 通了。

### 文字左右颠倒 / 整屏镜像

这是 MADCTL 的 MX 位问题，不是字体数据问题（固件里的点阵字库是正确方向，
已用 host 端复刻 `draw_glyph()` 渲染验证过）。

先按 **BOOT 键**循环方向，看哪个位置文字正常。若都不对，检查 Kconfig 里
`TFT_ROTATION` 相关的方向配置。

### 花屏 / 颜色不对

- 红蓝互换 → 打开 `TFT_BGR`
- 整体颜色反相（像负片）→ 打开 `TFT_INVERT_COLOR`
- 画面旋转 90° → 把 `TFT_ROTATION` 改成 90 或 270
- 花屏 → 把 `TFT_PCLK_HZ` 降到 20000000，缩短杜邦线

### 串口日志刷屏但屏幕不动

检查 `CS` 和 `DC` 是否接反 —— 这两个最容易接错，且接错时程序不会报错，只是不显示。

## 内存说明（重要）

本板是 ESP32 rev 1.1，**没有 PSRAM**。240×320×2 = 153600 字节的帧缓冲无法作为一整块连续内存分配（最大 DRAM 堆区约 154 KiB，Wi-Fi 驱动还要占一大块）。

因此 `tft_disp.c` 把帧缓冲**拆成 10 块 16 KiB** 分别分配，绘制 API 对上层透明，不受影响。

日志里的这行是正常的：
```
W (811) tft_disp: PSRAM unavailable, frame buffer in internal RAM
```

固件启动后剩余可用堆约 60 KB，属于正常范围。

## 内存与分区占用

| 项 | 值 |
|---|---|
| firmware.bin | 1,096,800 字节（≈ 1071 KB） |
| app 分区 | 0x100000 → 0x210000（**2 MB**） |
| storage 分区 | 0x210000 → 0x310000（1 MB） |
| app 分区剩余 | 约 1 MB |

> ⚠️ 分区表已从「1 MB app」改为「2 MB app + 1 MB storage」以容纳扩大的中文字库。
> 分区表在 flash `0x8000`，改变布局后**必须先 `erase-flash` 再刷写**，
> 否则引导程序按旧分区表找不到 app，设备无法启动。
> `erase-flash` 会清除 NVS 中的 Wi-Fi 配置。

板载 Flash 实测 4 MB，2 MB app 分区仍有约 1 MB 余量。

## 中文显示

固件内置 **GB2312 一级 + 二级汉字（6763 字）+ 常用标点 + ASCII**，共 6976 个字形，
以 16×16 点阵存储，中文 16 px 宽、ASCII 9 px 宽（西文与中文共享基线）。

### 字库放在 flash 里，不占 RAM

字库共 **218 KB**，超出剩余堆内存，所以通过 ESP-IDF 的 `EMBED_FILES`
打进固件的 flash，运行时按码位二分查找、按需读取 —— **不占用任何 RAM**。
实测固件启动后可用堆 48800 字节 / 最低堆 44476 字节，
与引入中文字库前的 48604 / 44272 基本一致（差值来自代码本身）。

### 字库覆盖范围

GB2312 覆盖了绝大多数日常用字，但不包含生僻字和繁体字。
**字库外的字符降级显示为 `?`**（不会画成方框，避免与真实字形混淆）。

实测环境中的 SSID「南迦巴瓦」中的「迦」属 GB2312 二级字，已包含在库内。

### 生成字库

```bash
cd firmware/tools
python3 gen_cjk_font.py     # 需要 pillow
```

产物：

| 文件 | 说明 |
|---|---|
| `components/ili9341/include/font_cjk16.bin` | 字形数据（218 KB） |
| `components/ili9341/include/font_cjk16_cp.h` | 码位表（Unicode 码点数组） |

字库里的 **ASCII 槽位直接复用 `font9x13.h` 的原始字节**（9×13，底部对齐到
16×16 单元格），保证中英混排时西文字形与 ASCII 字体完全一致、基线对齐。

### 绘图 API

```c
/* 中文/西文混排，自动 UTF-8 解码与变宽排版 */
tft_draw_text_cjk(disp, x, y, "Wi-Fi 网络列表", TFT_COLOR_CYAN, 1);

/* 按像素宽度裁剪（超出加省略号） */
tft_clip_text_cjk(dst, sizeof(dst), ssid, 100);

/* 测量宽度 */
tft_text_width_cjk("状态：已连接");
```

原有的 `tft_draw_text()` / `tft_draw_text()` 等 ASCII 接口保持不变，
中文文本请使用 `_cjk` 版本。

### 加字的注意事项

字库外的汉字会显示为 `?`。改字库：

1. 编辑 `firmware/tools/gen_cjk_font.py` 里的 `EXTRA` 字符串，加入新字
2. 重新运行 `python3 gen_cjk_font.py`
3. 重新编译烧录

代价是每个汉字 32 字节 —— 加 100 个字约多占 3.2 KB flash。

生成器顶部的 `CHAR_SET` 控制汉字范围：

| 值 | 内容 | 字库大小 | 分区要求 |
|---|---|---|---|
| `"l1"` | 一级 3755 字 | 124 KB | 1 MB app 即可 |
| `"l1l2"` | 一级 + 二级 6763 字 | 218 KB | **需 2 MB app** |

改字库后必须确认 `firmware.bin` 没超过 app 分区大小。

### 验证中文渲染

真机无法直接观察时，用这两个手段取证：

```bash
# 1. 固件自报屏幕文本 + 缺字码位（@PAGE 回包）
#    missing 字段为空即表示该行无缺字
@CMD PAGE

# 2. host 端复刻渲染：直接编译固件的 tft_cjk.c，
#    用真实字库数据走同一套查找与位提取逻辑
```

> **坑**：host 端自写渲染器时，16×16 字形每行是 **2 字节**，
> 取位必须是 `data[row*2 + (gx>>3)] & (0x80>>(gx&7))`。
> 只取每行第 1 个字节会让右半边 8 像素全丢，看起来像「中文乱码」，
> 但固件本身其实是对的。
